# A/B tests

Generated by `python -m tools.ab_tests --out docs/ab`. Raw numbers: `docs/ab/*.json`. Variant A is the current system; `winner` marks the best variant per group (`tie` = equal).

## Method and sources

All experiments run the same inputs through variant A (current) and B/C by monkeypatching `sot` at runtime (`tools/ab_tests.py`; `sot/**` is untouched). Seeds are fixed, so a re-run gives the same numbers (timings vary).

- Entity resolution is scored pairwise: over all record pairs, a pair is a true positive when both records are in the same predicted person and the same true person; precision = TP/(TP+FP), recall = TP/(TP+FN), F1 their harmonic mean. Accuracy is meaningless under this class imbalance. Hand and Christen (2018) also warn that F1 weights precision and recall differently per method, so the table shows P and R next to F1. https://openresearch-repository.anu.edu.au/items/e3bc0e58-14c1-43a5-b1fa-78b3fdbdcd10 , overview of pairwise measures: https://ijpds.org/article/view/3102
- Table extraction is scored by cell accuracy: cells equal to the ground truth (whitespace removed, as PDFs hard-wrap) divided by max(rows found, rows true) x columns, so missing or extra rows count as wrong. The literature uses finer measures (ICDAR 2013 directed adjacency relations, TEDS, GriTS: https://arxiv.org/pdf/2203.12555 ; survey of these: https://arxiv.org/pdf/2603.18652 ); on these inputs rows are all-or-nothing, so cell accuracy separates the variants.
- Pipeline-level numbers use the chaos runner's rules (recall = expected issues found, precision = matched / issues of the planted kinds, golden equality = persons and credentials equal the clean-file baseline); metamorphic idea: https://dl.acm.org/doi/10.1145/3143561
- Limits: all worlds are synthetic (about 100 surnames, so 40-80 staff), the foreign PDFs are 8 documents from 5 renderers, the real-world CSV set is 9 files. Differences under one document or one world are noise.

**Interpretation.** link.auto 0.95 (A) and 0.90 (B) give identical pairwise results on all 14 worlds (P 1.000, R 0.997, F1 0.999): no pair scores between 0.90 and 0.95, so lowering it changes nothing and gains nothing. 0.98 (C) loses recall (98.2% vs 99.7%; 84 vs 12 missed pairs) because true links with prob 0.95-0.98 fall into the gray zone (75 gray pairs vs 6) with no precision gain, since precision is already 1.000. The 12 missed pairs of A are 3 per world in 4 worlds (cause not analysed here; they are the same 3 pairs in every affected world, i.e. one planted defect). 0.95 is justified; 0.90 is equivalent here, so the choice between them rests on the larger-population evidence in docs/research/A4.md (0.90 gained nothing there either). Caveat: these worlds have unique full names for almost everyone, so precision cannot drop; the high-collision case is only in A4 (600 people). Winner: A = B (tie); C clearly worse.

## 4. Shift hours source (RC12)

| condition | variant | n | false_HRS_PAID_VS_SCHED | true_HRS_found | LEGEND_MISMATCH_found | winner |
|---|---|---|---|---|---|---|
| legend_mismatch only | A current: hours from times | 10 | 0 | 0/0 | 10/18 | yes |

| no defects | A current: hours from times | 10 | 0 | 0/0 | 0/0 | tie |
| no defects | B legend-first | 10 | 0 | 0/0 | 0/0 | tie |
| legend_mismatch + paid_vs_scheduled_delta | A current: hours from times | 10 | 0 | 10/10 | 10/18 | yes |
| legend_mismatch + paid_vs_scheduled_delta | B legend-first | 10 | 38 | 10/10 | 10/18 |  |

**Interpretation (decision RC12).** Hours from the shift times (A) is clearly right and legend-first (B) is clearly wrong. In 10 worlds with `legend_mismatch_token` (footnote says 11p-7a is 9 h, the times say 8 h) A raises 0 false HRS-PAID-VS-SCHED issues and B raises 40 (about 4 per world, from the 1 h difference per night shift exceeding the pay tolerance). With the paid-vs-scheduled delta planted too, both find all 10 true issues, so B gains no recall; it only adds 38 false ones. On worlds without the defect both raise 0, so the legend choice only matters when the legend is wrong, which is exactly when B is harmful. Both variants emit the same LEGEND-MISMATCH issues (10 of 18 expected; the shortfall is identical under A and B, so it is a recall gap of the legend cross-check itself, not an A/B effect, and was not analysed further). Winner: A. Matches the B4 evidence quoted in TASKGRAPH §6.

Side note: in the first run of this experiment, before an upstream change landed during the wave, A also raised 39 false HRS issues per 10 clean worlds because weekday columns such as `Wed 09/16` resolved to 2020-09-16 (same calendar as 2026) via HR hire dates used as year anchors; the final run no longer shows it (0 false for A on clean worlds). Worth a regression test.

**Interpretation (headline).** 23 of 24 worlds ran (seed 7); one crashed in the raster-PDF path (`Pipeline.poll_agents` -> `KeyError: 'file_id'`, orchestrator.py:126, chaos stand-in page reader), which the table excludes. The mutation noise therefore costs about 9 points of recall and 29 points of precision, mostly false issues rather than lost ones: see `chaos.json` (`mutated_unexpected_by_check`: HRS-PAID-VS-SCHED 95, FAC-MISMATCH 36, SCHED-NO-HR 22, PARSE-UNKNOWN-VALUE 18, ROW-INCOMPLETE 18 against 25 / 0 / 3 / 0 / 0 on clean files) and the missed kinds (`clean_missed_by_check`: LEGEND-MISMATCH 18, PARSE-DATE 12). Nine golden-equality failures are persons or credentials that appear or vanish between clean and mutated ingest (see `golden_failures`). Not a choice between variants: these are the numbers to track, and they are the largest open gap (mutated-file precision), not any of the tuned knobs above.
