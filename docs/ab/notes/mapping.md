**Interpretation.** The combined score with the value gate (A) is the best or tied-best everywhere and is justified. On clean README CSVs and the real-world HR rosters all three variants are perfect (the README files are too clean to separate them, as docs/research/A3.md found). The separation comes from mutated files: header-only (B) falls to 94.3% column accuracy on 1-3 chained mutators and 96.6% on single mutators, and it picks the wrong template for payroll and licence files once an unknown extra column (`Notes`, `Batch`, `Dept Code`) is added (e.g. `payroll_id` -> `person.employee_id`, `period_start` -> `person.given_name`): without a value check a header-only match has no way to reject a column whose values do not fit. Value-only (C) is right on the single mutators and on templates (100%), but loses on chained mutators (98.1% column accuracy): with reordered/synonym headers it swaps look-alike columns (`Verified` <-> `Expiration Date`, both dates) and gives an unknown column `Dept Code` the field `pay.payroll_id`, which a header would have refused. On the 6 unrelated real-world CSVs (CMS PBJ, CO/TX licences, NYC/Chicago payroll) no variant auto-maps (0/6 false auto-maps), so that guard comes from the template-coverage rule, not from the score blend. Winner: A (mutated CSVs: 100% vs 94.3% vs 98.1%). No B/C variant wins anywhere.
