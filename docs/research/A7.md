# A7 front end: research and API contract

Stack: Vite 8 + React 18 + TypeScript + Tailwind v4 + React Router 7 (declarative) + Vitest/Testing Library. Plain tables (no TanStack Table: the tables are small and static, so it would add code).
Run: `cd frontend && npm i && npm run dev:mock` (no backend) or `npm run dev` (proxies /api to :8000); `npm run build` -> `frontend/dist`; `npm test -- --run`.

## Sources and decisions
- https://tailwindcss.com/docs/installation/using-vite : v4 needs only `@tailwindcss/vite` in `vite.config.ts` and `@import "tailwindcss";` (no tailwind.config, no postcss).
- https://vite.dev/config/server-options#server-proxy : `server.proxy {"/api": "http://localhost:8000"}`; SSE passes through.
- https://vite.dev/guide/env-and-mode : `VITE_MOCK=1` read as `import.meta.env.VITE_MOCK`; tests set it via vitest `test.env`.
- https://developer.mozilla.org/en-US/docs/Web/API/EventSource : named SSE events (`event: <type>`) are NOT delivered to `onmessage`; we `addEventListener` for every type in `EVENT_TYPES`. The browser auto-reconnects (and the backend replays), so the client closes the stream on run.completed / run.failed and dedupes by `seq`.
- https://developer.mozilla.org/en-US/docs/Web/API/FormData : multipart upload, repeated field `files`; do not set Content-Type manually.
- https://reactrouter.com/start/declarative/routing : `Routes`/`Route`/`NavLink`/`Navigate`.
- https://vitest.dev/config/ : jsdom environment, globals, setupFiles.
- https://developer.mozilla.org/en-US/docs/Web/API/HTML_Drag_and_Drop_API/File_drag_and_drop : drop zone.

Pure logic (all unit-tested in `src/lib/logic.test.ts`): `groupEvents`, `parsePbj`/`filterPbj`, `sortIssues`/`groupBySeverity`, `bucketCredentials`, `parseHighlight`.
Build note: mock code is bundled into the production build too (about 10 kB); it is only used when `VITE_MOCK=1`.

## API contract (what the UI expects; TS in `frontend/src/api/types.ts`)
Names mirror `backend/sot/core/models.py`. Dates are ISO strings. Optional fields may be null or absent.

| Endpoint | Response shape |
|---|---|
| POST /api/ingest (multipart, field `files`, repeated) | `{run_id}` |
| GET /api/runs | `RunInfo[]` = `{run_id, started_at, finished_at\|null, status, file_count}`, newest first. UI replays `[0]` on page load |
| GET /api/runs/{id}/events (SSE) | `event: <EventType>` + `data: <Event JSON>`; `file_name` set for per-file events. `data` keys: `file.sniffed {parser, score, bids: SniffResult[]}`; `table.extracted {table_id, page?, sheet?, method, score, rows}`; `table.mapped/drift/unmapped {table_id, template_id\|null, confidence, matches: FieldMatch[], unmapped_columns}`; `agent.task_* {task_id, kind, ref}` |
| GET /api/summary | `RunSummary` minus `run_id`, but `agent_tasks` is `{[AgentStatus]: count}` (IMPLEMENTATION s17) and `issues_by_severity` is `{[Severity]: count}` (active issues) |
| GET /api/issues?severity&status&check_id&active | `IssueListItem[]` = `Issue` without `evidence`, plus `evidence_count: number`, `person_name: string\|null` |
| GET /api/issues/{fingerprint} | `Issue` (with `evidence: EvidenceItem[]`) plus `person_name`. EXTENSION: `EvidenceItem.raw?: {[column]: string\|null}` = the source row for CSV/XLSX cell items (UI renders a mini table, highlights `loc.col`) |
| PATCH /api/issues/{fingerprint} body `{status, owner?, note?}` | updated `IssueDetail` |
| GET /api/evidence/crop?file_id&page&x0&top&x1&bottom&pad | `image/png`, header `X-Highlight: x,y,w,h` as fractions (0..1) of the crop image (x,y = top-left). Same-origin, so the header is readable |
| GET /api/people | `PersonRow[]` = `{person_id, employee_id\|null, has_hr, display_name, role, home_facility_id, phone, hire_date, issue_count}` |
| GET /api/people/{id} | `{person: PersonRow, golden: GoldenField[], links: Link[], credentials: Credential[], shifts: PersonShift[], issues: IssueListItem[]}`; `GoldenField` = `GoldenValue` + `claims: Claim[]` (all claims for that attribute, golden one has `claim_id == golden.claim_id`); `PersonShift` = `{shift_id, facility_id, role, work_date, token, hours, loc}` |
| GET /api/shifts?start&end&facility | `{days: string[], facilities: [{facility_id, name, rows: [{person_id, display_name, role, cells: {[date]: {token, hours, license_valid}}}], rn_coverage: {[date]: hours}}]}` (missing date key = no shift; coverage under 8 h renders red) |
| GET /api/credentials?horizon_days=90 | `Credential[]` = `{credential_id, holder_type: "person"\|"organization", holder_id, holder_name, credential_type, number, issued_on, expires_on, last_verified, days_left}` (UI buckets by `days_left`: <0, 0-30, 31-60, 61-90) |
| GET /api/contracts | `Contract[]` (models.py) |
| POST /api/contracts/{id}/approve | `Contract` |
| GET /api/agent-tasks?status | `AgentTask[]` (models.py; `output_schema` not needed) |
| GET /api/exports/pbj.csv | CSV, header exactly `employee_id,person_id,facility_id,work_date,job_code,hours,status,note`; `status` is `ready` or `needs_signoff`; RFC 4180 quoting |
| GET /api/exports/issues.csv | CSV download (link only) |
| GET /api/settings, PUT /api/settings body `{as_of}` | `{as_of: "YYYY-MM-DD"}` |

Refetch rule: `RunProvider` (src/lib/RunContext.tsx) bumps a version on `run.completed` and `agent.task_accepted`; every `useApi` hook refetches. PATCH/PUT/approve also bump it.
