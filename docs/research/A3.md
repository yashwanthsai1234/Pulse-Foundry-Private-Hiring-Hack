## A/B: header-only vs value-only vs type-only vs combined (0.45/0.45/0.10)
Cases: 3 README CSVs, mangled payroll headers (`Emp,Cls,Site,Wk Beg,Wk End,Hrs,Ref`), generic headers (`c0..c6`),
wrong headers (headers shuffled against the data), vendor file. Entry = correct columns / expected, then confidence.

| case | header-only | value-only | type-only | combined |
|---|---|---|---|---|
| hr_roster | 9/9, 1.00 | 9/9, 1.00 | 9/9, 1.00 | 9/9, 1.00 |
| payroll | 7/7, 1.00 | 7/7, 1.00 | 7/7, 0.92 | 7/7, 0.99 |
| license | 5/5, 1.00 | 5/5, 1.00 | 5/5, 1.00 | 5/5, 1.00 |
| mangled payroll | 7/7, 1.00 | 7/7, 1.00 | 7/7, 0.92 | 7/7, 0.99 |
| generic headers c0..c6 | 0/7, template None | 7/7, 1.00 | 7/7, 0.92 | 7/7, **0.67** |
| wrong headers (shuffled) | 6/7, 0.55 | 7/7, 1.00 | 7/7, 0.92 | 7/7, **0.82** |
| vendor file | 6/6, 1.00 | 6/6, 1.00 | 6/6, 1.00 | 6/6, 1.00 |
| garbage values, good header | maps `Hours` (wrong) | - | - | `Hours` rejected (S capped 0.4 < 0.5) |

Findings:
1. On clean data every scheme works; the README tables are too small/clean to separate them (README values are very discriminating for this pack).
2. Header-only fails with no usable headers and trusts garbage values; value-only gets columns right but is over-confident (1.00 with `c0..c6`). Combined gives the right columns AND a confidence that reflects the missing header evidence (0.67 -> routed to the `schema_mapper` agent, not auto-applied). That calibration is the reason to keep the blend.
3. Type-only is weak on its own (integer vs number, strings) but is a cheap tie-break (10%).

## Deviations from the spec (each found by a failing test)
1. **Template choice ranks by confidence x share of columns explained** (reported confidence remains coverage x quality). Evidence: a payroll table with generic date headers (`Date A`, `Date B`) was classified `vendor_credential` at 0.955, because that template only requires `org.name` + a date and `Name` + two dates satisfy it. Weighted by columns explained (4/7) it loses to payroll.
2. **`non_empty` validators count only behind a strong header (>= 0.8).** `credential.doc_type` has a validator that every string passes, so any column (e.g. `Hours` = "lots") scored ~0.77 for it. Now such fields get value_score 0 unless the header already matches.
3. **single_name_token also excludes vocab values**, like person_name, otherwise "Registered Nurse" and "Harborview Bayside" (2 alpha tokens) validate as given names.
4. **Vocab fuzzy skips 1-character values** (token_set_ratio gives 100 for token subsets, so "n" would hit "r n").
5. **Fingerprint collapses digits** (`Mon 09/14` and `Mon 09/21` hash the same) so a weekly schedule does not drift every week. Contract application maps by the same normalized names.
6. `save_contract` gained an optional `export_dir` argument (YAML mirror; YAML omits `approved` since the DB is the truth). `resolve_weekday_date` returns `date | None` (TASKGRAPH signature, not the IMPLEMENTATION tuple). Day-first twin ambiguity requires that the two readings actually differ.
7. `shift_token_or_off` validator reuses A2's `parse_shift_token`.
